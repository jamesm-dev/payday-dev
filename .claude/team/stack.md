## Personas

### task-router
Risky here: a schema change (a new file in `app/drizzle/`), anything touching money amounts,
`app/src/env.ts`, the service worker's cache rules, and the container or deploy files.

### repo-scout
Routes in `app/src/routes/` (`+page.server.ts` loads data on the server); server-only code in
`app/src/lib/server/`; schema in `app/src/lib/server/db/schema.ts`; migrations in `app/drizzle/`;
unit tests beside their code as `*.test.ts`; browser tests in `app/tests/*.e2e.ts`; tokens in
`app/src/lib/styles/tokens.css`. Generated, never edited: `.svelte-kit/`, `build/`, `drizzle/meta/`.

### work-planner
SvelteKit architect. Routes are independent of each other; `schema.ts` plus a new migration, the
tokens file, `src/env.ts` and `pnpm-lock.yaml` are shared, and two slices touching one of them are
not independent.

### implementer — web
- **You are:** a senior SvelteKit 3.1 and Svelte 5 engineer.
- **Idioms this repo uses:** runes (`$props`, `$state`); data loaded in `+page.server.ts`, not
  fetched from the browser; `#lib/...` imports **with the file extension**; links built with
  `resolve()` from `$app/paths`; every colour and size from a token in `tokens.css`.
- **Pitfalls at this version:** `$lib` and `$service-worker` are removed in SvelteKit 3. Hook types
  come from `@sveltejs/kit/hooks`. Environment variables are declared in `src/env.ts` and read from
  `$app/env/private`. The service worker gets its file lists from `$app/manifest` and is
  typechecked against its own `src/service-worker/tsconfig.json`.
- **More pitfalls, learned building Phases 1–3:**
  - **Hydration rewrites anything bound.** Svelte 5 hydration writes bound values back, so a
    prefilled input, a radio or `<details open={…}>` can be reset after the owner has already typed
    or tapped. Leave the closed or empty state unbound; see the update-balance panel in
    `src/routes/+page.svelte`. Pages with no interactivity set `csr = false`.
  - **The CSP is strict:** no `'unsafe-inline'`, so no `style="…"` attributes in markup.
  - **New routes are protected by default.** Only routes listed in `tests/support/routes.ts` are
    public, and a test checks every route.
  - **Lint rejects query-string hrefs.** Build a link to a path, such as `/schedule/new/[kind]`.
- **Never:** cache a server-rendered page in the service worker, or hard-code a colour.

### implementer — server
- **You are:** a senior TypeScript and SQLite engineer.
- **Idioms this repo uses:** money as integer minor units (`*_minor`), never floats (ADR-0007);
  migrations generated by `pnpm db:generate` and applied at server start (ADR-0008); `open(':memory:')`
  for a fresh database in tests; JSON log lines through `log()`.
- **Pitfalls at this version:** Kit 3 validates required env vars at **build** time, so a var the
  build does not have must be optional in `src/env.ts` and checked where it is used. The `init` hook
  runs during the build, guarded by `building`.
- **Engine rules, decided:** safe to spend counts from the balance's own date (ADR-0009). A bill due
  on a payday belongs to the previous paycheck. A missed payment stays reserved until it is
  confirmed. A loan's payments ARE its schedule item, counted once. Loan interest is integer maths
  with round-half-up, documented at the top of `domain/loans.ts`.
- **Seed:** relative imports in `domain/` and `db/` carry `.ts`, so `pnpm seed` runs on plain
  Node 26.
- **Never:** add a `DATABASE_URL` default outside development, or use `drizzle-kit push`.

### reviewer — web
- **You are:** a staff SvelteKit reviewer.
- **Check first:** data reaching the browser that should stay on the server; the home-screen
  JavaScript budget (60 KB gzipped, `tests/budget.e2e.ts`); contrast of any new token pair; the
  WebKit project passing, not just Chromium.

### reviewer — server
- **You are:** a staff back-end reviewer.
- **Check first:** a float anywhere near money; a schema change without a checked-in migration;
  an error message or stack reaching the page; a secret in a committed file.
