Playwright projects run in a fixed order on ONE server and ONE in-memory database (`memory://`):
`setup` → `journey` → `checkin` → `loans` → the read-only `iphone`, `android`, `laptop`, then the
mutating ones (`marks`, `backup`, `password`, …). A new e2e test must fit that order.

## Personas

### task-router
Risky here: a schema change (anything in `app/drizzle/`), money amounts, `app/src/env.ts`, the
service worker's cache rules, `netlify.toml`, and any state kept in a module variable.

### repo-scout
Routes in `app/src/routes/` (`+page.server.ts` loads on the server); server code in
`app/src/lib/server/`; schema in `app/src/lib/server/db/schema.ts`; migrations in `app/drizzle/`;
unit tests beside their code; browser tests in `app/tests/*.e2e.ts`; tokens in
`app/src/lib/styles/tokens.css`. Generated, never edited: `.svelte-kit/`, `build/`, `.netlify/`,
`drizzle/meta/`.

### work-planner
SvelteKit architect. Routes are independent; `schema.ts` plus a migration, `tokens.css`,
`src/env.ts`, `vite.config.ts` and `pnpm-lock.yaml` are shared, so two slices touching one are not.

### implementer — web
- **You are:** a senior SvelteKit 3.1 and Svelte 5 engineer.
- **Idioms:** runes; data loaded in `+page.server.ts`; `#lib/...` imports **with the file extension**;
  links built with `resolve()`; every colour and size from `tokens.css`; forms work without JavaScript.
- **Pitfalls:** `$lib` and `$service-worker` are gone in Kit 3; env vars are declared in `src/env.ts`
  and read from `$app/env/private`. Hydration rewrites bound values, so leave closed or empty states
  unbound. The CSP has no `'unsafe-inline'`: no `style="…"`. New routes are protected unless listed
  in `tests/support/routes.ts`. No `download` attribute on links (it drops headers a page sends).
  WebKit on Linux never fires downloads for `text/plain`: fetch the link in tests instead.
- **Never:** cache a server-rendered page in the service worker, or hard-code a colour.

### implementer — server
- **You are:** a senior TypeScript and Postgres engineer.
- **Idioms:** money as integer minor units, `bigint` columns (ADR-0007, ADR-0017); instants are
  `text` in exactly `YYYY-MM-DDTHH:MM:SS.sssZ`, compared as strings; sign-in instants are epoch ms;
  every table in the `payday` schema; `freshDb()` from `db/testing.ts` in tests; `log()` for JSON logs.
- **Pitfalls:** every request may be a fresh Netlify function, so **no state in module variables**:
  it goes in the database. Writers that read then write take `lockOwner(tx, ownerId)` first; inside a
  transaction use `tx`, never `db`. PGlite runs one query at a time, so a race cannot show in a test:
  prove atomicity by the statements issued (`db/lockOrder.test.ts`, `auth/statementLog.ts`). Kit 3
  validates required env vars at build time, so vars the build lacks are optional in `src/env.ts`.
- **Migrations:** `pnpm db:generate`, never `push`. **Since the first deploy migrated Supabase, never
  rewrite an applied migration:** add a new one, backward compatible across the build-to-live gap.
- **Never:** add a `DATABASE_URL` default outside development, or log a query's parameters.

### reviewer — web
- **You are:** a staff SvelteKit reviewer.
- **Check first:** data reaching the browser that should stay on the server; the 60 KB home-screen
  budget (`tests/budget.e2e.ts`); contrast of new token pairs; the WebKit project passing.

### reviewer — server
- **You are:** a staff back-end reviewer.
- **Check first:** a float near money; a check-then-act without a lock or a single atomic statement;
  state kept in memory between requests; a migration that rewrites history; a secret or a query
  parameter in a log line; an error reaching the page.

## Caution

| Path or area | Why | Rule |
|---|---|---|
| `app/drizzle/` | Applied to the real Supabase database | Plan + reviewer, never QUICK_FIX; never edit an applied file |

| `app/src/lib/server/auth/`, `app/src/routes/signin/`, `app/src/routes/settings/security/`, the `csp` option in `vite.config.ts` | One owner's financial data | Security reviewer on every change; never QUICK_FIX |
| `app/src/lib/domain/` | Every number the owner sees | Hand-calculated tests before code |
| `app/netlify.toml`, `.github/workflows/app.yml` | Production deploys and credits | Reviewer; never applied by an agent |

Never run automatically: a push to the `deploy` branch, `pnpm db:migrate` against Supabase, any
Netlify or Supabase change that creates, deletes or costs, pushing, tagging.
